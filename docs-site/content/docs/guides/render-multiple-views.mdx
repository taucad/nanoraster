---
title: Render multiple views
description: Declare an ordered plan of identified camera views — with per-view size and format overrides — and render it in one call from one GLB.
---

Render several outputs of one model in a single call — the plan call — keeping
the IDs and order you declared, as [the tutorial](../tutorial) does for its
contact sheet. One call parses and uploads the GLB once, shares the GPU device
across every view, and schedules the whole set together, which a loop of
single renders never can.

### 1. Declare the views as a tuple

Each view needs a unique `id` and its own angles. `includeAxes` marks the
orientation of each one, which a set of angles alone does not show.

<RenderDemo>

```typescript
import { renderGlbToImages } from 'nanoraster';

import { readFile } from 'node:fs/promises';

const glb = Uint8Array.from(await readFile('model.glb'));

const images = await renderGlbToImages(glb, {
  format: 'webp',
  width: 640,
  height: 480,
  includeAxes: true,
  views: [
    { id: 'iso', phi: 60, theta: -45 },
    { id: 'front', phi: 90, theta: 0 },
  ],
});
```

</RenderDemo>

### 2. Read the results positionally or by ID

The result is a tuple, not a map: position and length match the input.

```typescript
const [iso, front] = images;

console.log(iso.id); // 'iso'
console.log(front.file.name); // 'thumbnail-front.webp'
```

TypeScript types `iso.id` as `'iso'` rather than `string`, but only while the
options object is inferred as const.

### 3. Ladder sizes and formats with per-view overrides

A view is more than a camera: `width`, `height`, `format` and `quality` can be
overridden per entry, defaulting to the shared values. One subject becomes a
card, a social image and a print asset in one call.

```typescript
const [card, og, print] = await renderGlbToImages(glb, {
  format: 'webp',
  width: 768,
  height: 576,
  views: [
    { id: 'card', phi: 60, theta: -45 },
    { id: 'og', phi: 60, theta: -45, width: 1536, height: 804 },
    { id: 'print', phi: 60, theta: -45, width: 1536, height: 804, format: 'png' },
  ],
});

console.log(og.file.name); // 'thumbnail-og.webp'
console.log(print.file.mimeType); // 'image/png'
```

Each entry's filename and MIME type follow its own resolved format, and
TypeScript narrows `print.file.mimeType` to `'image/png'` while `card` and
`og` stay `'image/webp'`. Overrides pass the same validation as the shared
values — a per-view `quality: 1` on WebP still means lossless, and annotated
views still need 192 pixels each way.

### 4. Preserve literal types across a variable

Assigning options to a variable widens the literals and loses the IDs;
`createRenderImagesOptions` prevents that without changing runtime behaviour.

```typescript
import { createRenderImagesOptions, renderGlbToImages } from 'nanoraster';

const options = createRenderImagesOptions({
  format: 'png',
  views: [
    { id: 'iso', phi: 60, theta: -45 },
    { id: 'top', phi: 0, theta: 0 },
  ],
});

const images = await renderGlbToImages(glb, options);
```

## Variations

**One image only.** Use `renderGlbToImage`. The batch call requires a non-empty
tuple and returns a tuple even for one view, under the same
[exactness rules](../api#renderglbtoimages).

**Labels on every view.** `includeLabel: true` makes `label` required on every
entry; see [Format and annotate](format-and-annotate).

**Shared-only settings.** `margin`, `up`, `projection`, `background`,
annotations and `lighting` apply to the whole request; only the camera pair
and the four output fields vary per view.

**Renders spread over time.** The plan call shares the device across views
_within_ one call; [`createRenderer`](reuse-the-renderer) shares it across
calls _over time_. They compose — a warm renderer accepts the same plan calls.
Either way, when you can write the full list of images down, send it as one
call rather than a loop: only the renderer can schedule work it can see.

**Stage timings.** `profile: true` attaches parse, setup, and per-view
render/encode milliseconds to the result as `results.profile`; see
[`RenderProfile`](../api#renderprofile).
