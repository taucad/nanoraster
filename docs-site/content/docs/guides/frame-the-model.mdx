title: Frame the model
description: Choose a fitted camera direction, screen-up vector, projection, and margin while nanoraster solves placement from referenced geometry.

A fitted camera chooses an orientation while nanoraster solves the optical
target, distance, and clip planes from indexed geometry that can be drawn. Use
it for thumbnails, contact sheets, and any capture that must keep the whole
subject in frame.

## Set direction and screen up

`direction` points from the subject toward the camera. `up` establishes screen
vertical and preserves roll. Both are Cartesian vectors in the declared caller
world; their magnitudes are ignored, and they must not be collinear. Fitting may
translate the camera and optical target together without changing orientation.

Omit `up` on a fit camera and it becomes the declared `world.up`. Supply it to
roll the camera, or to break collinearity when `direction` runs along that same
axis, as a plan view does.

<RenderDemo>

```typescript
import { renderImage } from 'nanoraster';

const image = await renderImage(glb, {
  format: 'webp',
  world: { up: '+z', forward: '-y', unit: 'meter' },
  camera: {
    framing: 'fit',
    direction: [0.6123724357, -0.6123724357, 0.5],
  },
});
```

</RenderDemo>

This worked request authors a three-quarter view in Z-up metres; nanoraster
converts it once to the GLB frame. The live azimuth and elevation controls
derive the Cartesian `direction` shown in the copyable code. Expand
**advanced · direction XYZ** for raw vector entry.

## Turn angles into directions

[`renderDirectionFromOrbit`](../api#renderdirectionfromorbit) converts orbit
angles to the Cartesian `direction` a fitted camera takes, and
[`renderOrbitFromDirection`](../api#renderorbitfromdirection) inverts it. Both
resolve their axes from the world you pass, so pass the same `world` the request
declares:

```typescript
import { renderDirectionFromOrbit, renderImage } from 'nanoraster';

const world = { up: '+z', forward: '-y', unit: 'meter' } as const;

const image = await renderImage(glb, {
  format: 'webp',
  world,
  camera: {
    framing: 'fit',
    direction: renderDirectionFromOrbit({ azimuth: 45, elevation: 30 }, world),
  },
});
```

Azimuth is the angle in the world horizontal plane, zero on `world.forward` and
positive toward the viewer's right; elevation is the angle above it. This
convention is the pair's own, not the one the removed `phi`/`theta` options
carried. The wire stays Cartesian: a turntable is a sequence of azimuths.

## Choose the fitted projection

Perspective is the default. Its `verticalFieldOfView` is the exact rectilinear
angle in degrees. An orthographic fit uses the same referenced geometry and
margin but removes depth scaling.

```typescript
const perspective = {
  framing: 'fit',
  direction: [1, 0.4, 1],
  projection: { kind: 'perspective', verticalFieldOfView: 52 },
} as const;

const plan = {
  framing: 'fit',
  direction: [0, 1, 0],
  up: [0, 0, 1],
  projection: { kind: 'orthographic' },
} as const;
```

Fit framing intentionally has no `zoom`: `margin` is its one size control.
Use a [fixed camera](place-the-camera) when a caller must own magnification.

## Set the empty border

`camera.margin` is the minimum empty fraction around contained fitted geometry,
from `0` to `0.5`; the default is `0.1`.

```typescript
const image = await renderImage(glb, {
  format: 'webp',
  camera: { framing: 'fit', margin: 0.02 },
});
```

Fitting uses `width / height`, so set the output size before tuning the margin.
Annotations may loosen a fitted camera to keep the model clear of their fixed
screen-space slots, and the non-limiting image axis may have more whitespace.
A fixed camera is never changed by annotations.

### Very wide perspective

The `1..179` degree range is rectilinear. Near 180 degrees, positive front
clearance can add whitespace beyond `margin`. Use a narrower field for
photographic framing; fisheye is a different projection.
