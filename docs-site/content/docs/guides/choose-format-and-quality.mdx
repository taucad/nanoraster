---
title: Choose a format and quality
description: Pick between PNG, WebP, and JPEG, decide when transparency is available, and tune the encoder quality.
---

Choose the output encoder for your use, and understand which combinations of
format and background are valid.

## Prerequisites

- Completed the [Quick start](../getting-started/quick-start).

## Steps

### 1. Pick the format

```typescript
import { renderGlbToImage } from 'nanoraster';

const image = await renderGlbToImage(glb, { format: 'webp' });
```

| Format | Alpha | Lossy | Use for                                              |
| ------ | ----- | ----- | ---------------------------------------------------- |
| `png`  | Yes   | No    | Exact pixels, diffing, transparent thumbnails        |
| `webp` | Yes   | Yes   | Web delivery at a fraction of the PNG size           |
| `jpeg` | No    | Yes   | Interop with tools that accept nothing else          |
| `jpg`  | No    | Yes   | Alias for `jpeg`; the filename keeps the `jpg` extension |

The result's `mimeType` reflects the true type, so `jpg` and `jpeg` both report
`image/jpeg`.

### 2. Decide on a background

The default background is transparent. That is only representable in PNG and
WebP.

```typescript
const image = await renderGlbToImage(glb, {
  format: 'jpeg',
  background: '#0c1015',
});
```

JPEG cannot store alpha, so a JPEG request must set an opaque background.
Omitting it fails with an `encode` failure rather than silently flattening onto
an arbitrary colour — see [Handle render failures](handle-render-failures).

Backgrounds accept `#RRGGBB`, `#RRGGBBAA`, or normalized straight-alpha RGBA:

```typescript
const image = await renderGlbToImage(glb, {
  format: 'png',
  background: [0.05, 0.06, 0.08, 1],
});
```

### 3. Tune quality for the lossy formats

```typescript
const image = await renderGlbToImage(glb, {
  format: 'webp',
  quality: 0.8,
});
```

`quality` runs from `0` to `1` and defaults to `0.92`. It has no effect on PNG,
which is lossless — passing it is harmless but does nothing.

## Variations

**Smallest useful thumbnail.** WebP at `quality: 0.75` with `width: 256` is
typically an order of magnitude smaller than the equivalent PNG, at a size where
the loss is invisible.

**Byte-exact comparison.** Use PNG. Lossy encoders are deterministic here for a
fixed request, but a format that discards information makes a poor baseline for
diffing renders across model revisions.

**Alpha over an unknown page background.** Use PNG or WebP and leave the
background transparent, then let the page composite it.
