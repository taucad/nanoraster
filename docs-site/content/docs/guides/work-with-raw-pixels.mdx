---
title: Work with raw pixels
description: Skip the encode with format raw, paint straight into a canvas, and compare renders pixel by pixel.
---

The fourth output format is none. `format: 'raw'` stops the pipeline after
readback and hands you the pixels themselves — for canvas display, custom
encoding pipelines, and pixel-level comparison in tests.

### 1. Know when pixels beat a file

An encoded file exists to be stored or transmitted. When the next step is a
canvas, an encoder of your own, or a diff, encoding is pure overhead — and in
a browser the file is _decoded again_ before it can be shown. At 960×720 the
encode plus decode round trip costs roughly 20 ms per frame that the pixels
path never spends.

```typescript
import { renderImage } from 'nanoraster';

const { bytes, width, height } = await renderImage(glb, {
  format: 'raw',
  width: 640,
  height: 480,
  phi: 60,
  theta: -45,
});
```

The options are [`RenderImageOptions`](../api#renderimageoptions) unchanged —
camera, background, lighting, and annotations all apply, and `quality` is
ignored exactly as PNG ignores it. The result is a
[`RenderedImageFile`](../api#renderedimagefile) like any other: `bytes` are the
frame, `width` and `height` are the shape to read them at, `name` is
`render.raw`, and `mimeType` is `application/octet-stream`.

### 2. Paint to a canvas

The rows are straight-alpha, sRGB-encoded, and tightly packed — exactly what
`putImageData` expects, with no premultiply step.

```typescript
const imageData = new ImageData(new Uint8ClampedArray(bytes.buffer), width, height);

const canvas = document.querySelector('canvas');
canvas.width = width;
canvas.height = height;
canvas.getContext('2d')?.putImageData(imageData, 0, 0);
```

For scaled display, build an `ImageBitmap` instead and let the browser resample:

```typescript
const bitmap = await createImageBitmap(imageData, { resizeQuality: 'high' });
```

### 3. Compute on the frame

Between the render and the paint sits the whole reason to skip the encoder: the
frame is a plain array, and anything you can write in a loop is available. The
tile below runs live in this page. It maps each pixel's luma through a colour
ramp — over the same memory the renderer filled, with no second buffer — and
paints the result. No decoder produced that picture and no CSS filter could
have: it came out of the arithmetic beside it. Move the camera and the loop
runs again on the new frame.

```typescript
import { renderImage } from 'nanoraster';

const { bytes, width, height } = await renderImage(glb, {
  format: 'raw',
  phi: 62,
  theta: -38,
  margin: 0.08,
});

// No copy and no decode: the ImageData reads the bytes the renderer wrote.
const frame = new ImageData(new Uint8ClampedArray(bytes.buffer), width, height);
const { data } = frame;

// One pass over that same memory: luma per pixel, then a heat ramp.
// Uint8ClampedArray rounds and clamps, so the ramp needs no bounds of its own.
for (let index = 0; index < data.length; index += 4) {
  const luma = (0.2126 * data[index] + 0.7152 * data[index + 1] + 0.0722 * data[index + 2]) / 255;
  data[index] = 255 * Math.min(1, luma * 2.4);
  data[index + 1] = 255 * (luma * 1.8 - 0.6);
  data[index + 2] = 255 * (0.7 - Math.abs(luma - 0.25) * 2.4);
}

const canvas = document.querySelector('canvas');
canvas.width = width;
canvas.height = height;
canvas.getContext('2d').putImageData(frame, 0, 0);
```

### 4. Know the shape

`bytes` is `width * height * 4`: row-major, top row first, four bytes per
pixel, no padding, straight alpha in sRGB. A 640×480 render is exactly
1,228,800 bytes. The pixels are
identical to what the encoded paths compress — the same determinism rules from
[How it works](../how-it-works) apply, so two renders of one request on one
host are byte-equal before any encoder gets involved.

### 5. Compare renders perceptually

[How it works](../how-it-works#determinism) advises comparing renders
perceptually across hosts rather than by hash; raw pixels are the tooling path
for that advice. A channel-wise diff needs no decoder:

```typescript
const difference = (a: Uint8Array, b: Uint8Array): number => {
  let total = 0;
  for (let index = 0; index < a.length; index += 1) {
    total += Math.abs((a[index] ?? 0) - (b[index] ?? 0));
  }
  return total / a.length;
};

const before = await renderImage(previousGlb, { format: 'raw', width: 512 });
const after = await renderImage(currentGlb, { format: 'raw', width: 512 });

console.log(`mean channel delta: ${difference(before.bytes, after.bytes).toFixed(3)}`);
```

## Variations

**On a warm renderer.** `Renderer.renderImage` takes the same request on a
reused device, and a whole turntable is one `renderImages` plan of raw views —
which may sit beside encoded ones in the same call;
[Reuse the renderer](reuse-the-renderer) covers when to hold one.

**Workers.** Frames transfer well: `postMessage(bytes, [bytes.buffer])` moves
one without a copy; [Render in the browser](render-in-the-browser) shows the
worker shape.

**When you do want a file.** Use the encoded paths;
[Format and annotate](format-and-annotate) picks the format. Re-encoding the
pixels yourself with another library forfeits the byte-identity the built-in
encoders guarantee across artifacts.
