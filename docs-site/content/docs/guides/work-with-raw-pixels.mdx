---
title: Work with raw pixels
description: Return a raw RGBA buffer from a render instead of an encoded file, and use it for pixel diffs, turntable video frames, textures and tensors — with no image decoder in Node.
---

`format: 'raw'` stops the pipeline after readback and hands you the frame
itself. Reach for it when the next step wants pixels rather than a file: a
pixel diff, a video or GIF frame, a texture upload, a tensor, a hash.

### 1. Know why an encoded file is a dead end in Node

Node ships no image decoder. There is no `ImageData`, no `ImageBitmap`, no
`createImageBitmap` and no canvas among its
[globals](https://nodejs.org/docs/latest-v24.x/api/globals.html), so a PNG or
WebP arriving in a Node process is a container nothing there can open. An
encoded file is where the pixels stop.

Undoing the encode means adding a decoder, and decoders are large: sharp
carries about 19.6 MB of libvips prebuilds, node-canvas 7 to 21 MB plus an
install-time download, `@napi-rs/image` about 17.7 MB, jimp 3.3 MB across 27
packages. Only the [@jsquash](https://github.com/jamsinclair/jSquash)
WebAssembly codecs stay under a megabyte. A lossy round trip is not
pixel-exact either, so a hash or a palette taken after one describes the
encoder's output rather than the render.

### 2. Read the layout, which is not the obvious one

`bytes` is straight-alpha — un-premultiplied — sRGB RGBA8: exactly
`width * height * 4` bytes, row-major, top row first, four bytes per pixel, no
padding. A 640×480 render is 1,228,800 bytes.

```typescript
import { renderImage } from 'nanoraster';

const { bytes, width, height } = await renderImage(glb, {
  format: 'raw',
  width: 640,
  height: 480,
});
```

Every clause there is load-bearing, because the neighbours disagree with each
other. resvg-js returns a premultiplied `Pixmap` from `.pixels` while its own
`asPng()` is straight ([resvg-js#123](https://github.com/yisibl/resvg-js/pull/123)).
node-canvas `toBuffer('raw')` is native-endian BGRA with stride padding, while
`getImageData` on the same canvas is straight RGBA. headless-gl reads
bottom-left first. Check the contract before piping one library's buffer into
another's.

Otherwise the request is [`RenderImageOptions`](../api#renderimageoptions)
unchanged — camera, background, lighting and annotations all apply, and
`quality` is ignored exactly as PNG ignores it. The result is a
[`RenderedImageFile`](../api#renderedimagefile) like any other, with `name` set
to `render.raw` and `mimeType` to `application/octet-stream`.

### 3. Diff two renders without a decoder

[pixelmatch](https://github.com/mapbox/pixelmatch) takes two RGBA buffers and
their shape, and ships no decoder by design. Playwright's own
[comparator](https://github.com/microsoft/playwright/blob/main/packages/utils/comparators.ts)
runs `PNG.sync.read()` before calling it — a decode that exists only to undo an
encode.

```typescript
import { renderImage } from 'nanoraster';
import pixelmatch from 'pixelmatch';

const options = { format: 'raw', width: 512, height: 512 } as const;
const baseline = await renderImage(baselineGlb, options);
const candidate = await renderImage(candidateGlb, options);

const diff = new Uint8Array(baseline.bytes.length);
const changed = pixelmatch(baseline.bytes, candidate.bytes, diff, baseline.width, baseline.height);
```

[Determinism](../how-it-works#determinism) is what makes the count mean
something: the same request on one host produces the same bytes, so a non-zero
count is a change in the model or the request. Across hosts, expect a few
pixels of rasterization difference and set a threshold. A raw baseline also
answers the question an encoded one leaves open — with no encoder in the
comparison, a difference can only be the render.

### 4. Turn a turntable into video or GIF frames

A turntable is one [`renderImages`](../api#renderimages) plan of raw views
rather than a loop: the GLB is parsed and uploaded once, and the views
pipeline.

```typescript
import { GIFEncoder, applyPalette, quantize } from 'gifenc';
import { renderImages } from 'nanoraster';

const frames = await renderImages(glb, {
  format: 'raw',
  width: 480,
  height: 360,
  views: Array.from({ length: 36 }, (_, step) => ({ id: `f${step}`, phi: 60, theta: step * 10 - 180 })),
});

const gif = GIFEncoder();
for (const { file } of frames) {
  const palette = quantize(file.bytes, 256);
  gif.writeFrame(applyPalette(file.bytes, palette), file.width, file.height, { palette, delay: 40 });
}
gif.finish();
```

[gifenc](https://github.com/mattdesl/gifenc) quantizes and writes flat RGBA.
For video, the same buffers pipe into ffmpeg, where
[rawvideo](https://ffmpeg.org/ffmpeg-formats.html) is an input format:

```bash
ffmpeg -f rawvideo -pixel_format rgba -video_size 480x360 -framerate 25 -i pipe:0 turntable.mp4
```

The familiar route to a turntable is a screen recorder, a `.mov`, `palettegen`
and `gifsicle`. This one has no recorder, no intermediate container and no
display. A plan may also mix formats, so
`views: [{ id: 'thumb', format: 'webp' }, { id: 'frame', format: 'raw' }]`
returns the poster and the frames from one call;
[Render multiple views](render-multiple-views) covers the plan.

Count the memory before scaling it up. Every view in a plan arrives at once, at
`width * height * 4` each — 36 frames at 480×360 is 25 MB resident. For a long
sequence, hold a renderer and write each batch out before asking for the next;
[Reuse the renderer](reuse-the-renderer) is that loop.

### 5. Paint and upload in the browser

A browser has the decoder Node lacks, so what raw saves there is time. The
buffer is what every pixel sink already accepts:

```typescript
const frame = new ImageData(new Uint8ClampedArray(bytes.buffer), width, height);
canvas.getContext('2d')?.putImageData(frame, 0, 0);
```

The 3D paths take it with no wrapper at all —
`gl.texImage2D(…, gl.RGBA, gl.UNSIGNED_BYTE, bytes)`, WebGPU
`queue.writeTexture(destination, bytes, { bytesPerRow: width * 4 }, size)`,
three.js `new DataTexture(bytes, width, height)`, and WebCodecs
`new VideoFrame(bytes, { format: 'RGBA', codedWidth: width, codedHeight: height, timestamp })`.

Measured on the tile below at 960×720: 3.5 ms per frame painting the raw
buffer, against 8.6 ms for lossless WebP through `createImageBitmap`, and
27.8 ms to encode PNG before any decode. Worth having behind a slider, modest
in absolute terms, and browser-only.

<RenderDemo>

```typescript
import { renderImage } from 'nanoraster';

const { bytes, width, height } = await renderImage(glb, {
  format: 'raw',
  phi: 62,
  theta: -38,
  margin: 0.08,
});

// Straight-alpha sRGB RGBA8, top row first — the layout ImageData reads.
// No copy and no decode: this wraps the memory the renderer wrote.
const frame = new ImageData(new Uint8ClampedArray(bytes.buffer), width, height);

const canvas = document.querySelector('canvas');
canvas.width = width;
canvas.height = height;
canvas.getContext('2d').putImageData(frame, 0, 0);
```

</RenderDemo>

That tile is the render itself, painted from the bytes with nothing decoding
them on the way in, and the badge counts the frame the call returned. None of
this makes nanoraster a three.js alternative: it ships roughly twice the bytes
of three.js's WebGPU build, renders stills, and reads every frame back through
the CPU. Live interaction belongs to a canvas renderer.

### 6. Hand the buffer to a library

| Destination                   | The call                                                                                                            | Why raw                                             |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| Composite, resize, atlas      | [`sharp(bytes, { raw: { width, height, channels: 4 } })`](https://sharp.pixelplumbing.com/api-constructor)          | `premultiplied` defaults false, so nothing converts |
| AVIF, JPEG XL, QOI            | `@jsquash/avif` `encode(imageData)`                                                                                 | Formats nanoraster does not ship                    |
| TensorFlow.js                 | [`tf.browser.fromPixels({ data: bytes, width, height })`](https://js.tensorflow.org/api/latest/#browser.fromPixels) | `PixelData` is this buffer, named                   |
| Transformers.js               | `new RawImage(bytes, width, height, 4)`                                                                             | Its own input type                                  |
| Perceptual hash               | [`bmvbhash({ data: bytes, width, height }, 8)`](https://github.com/commonsmachinery/blockhash-js)                   | 3 KB of code, and no codec to feed it               |
| Terminal, kitty               | [`f=32` payload, `o=z` via `node:zlib`](https://sw.kovidgoyal.net/kitty/graphics-protocol/)                         | Raw RGBA is the protocol's default                  |
| Terminal, sixel               | `image2sixel(bytes, width, height)`                                                                                 | Palette-indexed, so every path quantizes from raw   |
| LED matrix, e-ink, `/dev/fb0` | `drawBuffer(bytes)`                                                                                                 | The device surface is a buffer                      |

### 7. Encode when the destination wants a file

Reach back for an encoded format whenever the consumer is a document, a wire,
or a viewer:

- **PDFs.** `pdf-lib` `embedPng` and `embedJpg` take encoded bytes.
- **Vision models.** Base64 PNG, JPEG, WebP or GIF;
  [Render for LLMs](render-for-llms) covers the shape.
- **glTF textures.** The specification permits `image/jpeg` and `image/png`.
- **`<img>`, HTTP, CDNs.** The browser decodes, so hand it something to decode.
- **iTerm2 inline images.** Base64 PNG, unlike kitty.

Re-encoding a raw frame with an encoder of your own also forfeits something the
built-in ones guarantee: identical bytes for an identical request, across every
artifact nanoraster ships. Once the encoder is yours, its version is yours to
pin.

## Variations

**Workers.** Frames transfer well: `postMessage(bytes, [bytes.buffer])` moves
one without a copy; [Render in the browser](render-in-the-browser) shows where
the renderer belongs.

**Annotations on a raw frame.** The axis indicator, label and scale bar are
drawn before readback, so they land in the buffer like everything else;
[Format and annotate](format-and-annotate) covers them.

**Scaled display.** `createImageBitmap(frame, { resizeQuality: 'high' })`
resamples in the browser; sharp's `raw` input does the same work in Node.
