---
title: Handle render failures
description: Classify a rejection, decide whether retrying can help, and keep the last good image when a GPU fault is transient.
---

Turn a rejected render into a decision: fix the input, retry the call, or fall
back.

## Prerequisites

- Completed the [Quick start](../getting-started/quick-start).

## Steps

### 1. Normalise whatever was thrown

`RenderError.from` returns an existing `RenderError` unchanged and classifies
anything else. It never throws, so it is safe as the first line of a `catch`.

```typescript
import { RenderError, renderGlbToImage } from 'nanoraster';

import { readFile } from 'node:fs/promises';

const glb = Uint8Array.from(await readFile('model.glb'));

try {
  const image = await renderGlbToImage(glb, { format: 'png' });
  console.log(image.name);
} catch (error) {
  const failure = RenderError.from(error);
  console.error(failure.code, failure.message);
}
```

### 2. Split transient faults from input faults

`isGpuFault` is true for the three codes that describe the device rather than
the request. Those are the only ones where retrying the same input can succeed.

```typescript
try {
  await renderGlbToImage(glb, { format: 'png' });
} catch (error) {
  const failure = RenderError.from(error);

  if (!failure.isGpuFault) {
    throw failure; // parse, encode, unknown — the request must change
  }

  // adapter-unavailable, device-lost, gpu — worth another attempt
}
```

### 3. Retry only the transient class

```typescript
import { RenderError, renderGlbToImage, type RenderedImageFile } from 'nanoraster';

const renderWithRetry = async (
  glb: Uint8Array<ArrayBuffer>,
  attempts = 3,
): Promise<RenderedImageFile> => {
  for (let attempt = 1; ; attempt += 1) {
    try {
      return await renderGlbToImage(glb, { format: 'png' });
    } catch (error) {
      const failure = RenderError.from(error);
      if (!failure.isGpuFault || attempt >= attempts) throw failure;
    }
  }
};
```

Retrying a `parse` failure loops forever over the same bad input, which is why
the guard checks the class before the attempt count.

### 4. Keep the last good image

In a pipeline that re-renders on every change, a transient GPU fault should not
blank an image that was previously fine.

```typescript
let lastGood: RenderedImageFile | undefined;

try {
  lastGood = await renderGlbToImage(glb, { format: 'png' });
} catch (error) {
  const failure = RenderError.from(error);
  if (!failure.isGpuFault) throw failure;
  // lastGood still holds the previous successful render
}
```

## Variations

**Distinguishing bad GLB from bad options.** Both surface as `parse`, because
both are input-contract violations. The `message` names which.

**JPEG with a transparent background.** Fails as `encode`, not `parse` — the
request is well-formed but the encoder cannot represent it. See
[Choose a format and quality](choose-format-and-quality).

**Unknown failures.** `unknown` means the thrown value carried no recognised
tag. Preserve `message` and the original context; do not retry.
