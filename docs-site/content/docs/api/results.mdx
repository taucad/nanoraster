What a render call gives back. Bytes are newly allocated and owned by the
caller; nanoraster never writes to disk.

## Single result

### `RenderedImageFile`

Returned directly by [`renderGlbToImage`](operations).

<auto-type-table path="./props.ts" name="RenderedImageFile" caption="RenderedImageFile properties" />

#### Usage

```typescript
import { renderGlbToImage } from 'nanoraster';

import { writeFile } from 'node:fs/promises';

const image = await renderGlbToImage(glb, { format: 'png' });
await writeFile(image.name, image.bytes);
```

## Batch results

### `RenderedImage`

One identified entry in a batch result. The `id` is the literal you supplied on
the matching view.

<auto-type-table path="./props.ts" name="RenderedImage" caption="RenderedImage properties" />

### `RenderedImages`

The tuple returned by [`renderGlbToImages`](operations).

```typescript
export type RenderedImages<Views extends readonly RenderImageView[]> = {
  readonly [Index in keyof Views]: Views[Index] extends RenderImageView<infer Id>
    ? RenderedImage<Id>
    : never;
};
```

This mapped tuple preserves each input view's literal ID, position, and tuple
length. It does not expose `Array` prototype members as result fields.

#### Usage

```typescript
import { renderGlbToImages } from 'nanoraster';

const [iso, top] = await renderGlbToImages(glb, {
  format: 'png',
  views: [
    { id: 'iso', phi: 60, theta: -45 },
    { id: 'top', phi: 0, theta: 0 },
  ],
});

console.log(iso.id, iso.file.name); // 'iso' 'iso.png'
console.log(top.id, top.file.name); // 'top' 'top.png'
```

## Output formats

### `imageMimeTypes`

The readonly runtime map of every accepted output format to its emitted MIME
type. `jpg` is an alias for `jpeg`; the filename keeps the requested extension
while the MIME type reports the true format.

```typescript
export declare const imageMimeTypes: {
  readonly png: 'image/png';
  readonly webp: 'image/webp';
  readonly jpeg: 'image/jpeg';
  readonly jpg: 'image/jpeg';
};
```
