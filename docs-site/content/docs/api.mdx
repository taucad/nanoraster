Every export on this page comes from `nanoraster`. The call owns the GLB
bytes that you pass in. Returned bytes are newly allocated, and you own them.

## Every option and its default

```typescript
import { renderImage } from 'nanoraster';

const image = await renderImage(glb, {
  format: 'webp', // required: 'png' | 'webp' | 'jpeg' | 'jpg' | 'raw'
  width: 768, // default
  height: 432, // default
  quality: 1, // webp default (lossless); jpeg defaults to 0.92; png and raw ignore it
  lineWidth: 3, // output pixels; default
  surfaces: true, // default
  lines: true, // default
  visiblePrimitives: undefined, // default (all reachable primitives)
  sections: undefined, // default (no section view)
  world: undefined, // default (glTF +Y up, +Z forward, metres)
  background: undefined, // default (transparent)
  axes: false, // default
  scaleBar: false, // default
  lighting: 'studio', // default
  label: undefined, // default (no label drawn)
  camera: undefined, // default fitted three-quarter perspective camera
});
```

`renderImages` accepts the same shared keys, except `label` and the singular
`camera`. It adds `views: [{ id, label?, camera?, width?, height?, format?, quality? }]`,
one entry per image in result order. It accepts `timings: true` to
attach stage timings.

## Render

### `renderImage`

Render one GLB camera view to one owned output.

```typescript
export declare const renderImage: (
  glb: Uint8Array<ArrayBuffer>,
  options: RenderImageOptions,
) => Promise<RenderedImageFile>;
```

- **Parameters:** owned GLB bytes and one validated render request.
- **Returns:** a newly allocated `render.<format>` file with the resolved
  width and height.
- **Throws:** `RenderError` for invalid requests, malformed GLB data, GPU faults,
  or encoding failures.

```typescript
import { renderImage } from 'nanoraster';

const image = await renderImage(glb, { format: 'webp', width: 512 });
```

### `renderImages`

Parse and upload a GLB once, then render an ordered set of identified views.
This is the plan call. Each view can override the shared `width`, `height`,
`format` and `quality`.

```typescript
export declare const renderImages: <const Options extends RenderImagesOptions>(
  glb: Uint8Array<ArrayBuffer>,
  options: StrictRenderImagesOptions<Options>,
) => Promise<RenderedImagesResult<Options>>;
```

- **Parameters:** owned GLB bytes and shared settings with a non-empty view tuple.
- **Returns:** a tuple that preserves the input view IDs and order. Each
  entry's MIME type follows its own `format` override.
- **Throws:** the same errors as `renderImage`, plus an error when the
  requested views and the returned images do not match.

```typescript
import { renderImages } from 'nanoraster';

const [iso, front] = await renderImages(glb, {
  format: 'webp',
  views: [{ id: 'iso' }, { id: 'front', camera: { framing: 'fit', direction: [1, 0, 0] } }],
});
```

## Renderer reuse

The one-shot functions share one renderer per process. The first call creates
it, and nothing disposes it.
Create your own renderer to control lifetime or power preference.
[Reuse the renderer](guides/reuse-the-renderer) covers when and how.

### `createRenderer`

Create a renderer that keeps the GPU device, shader and pipelines alive across
calls.

```typescript
export declare const createRenderer: (options?: CreateRendererOptions) => Promise<Renderer>;
```

- **Parameters:** optional GPU selection hints.
- **Returns:** a [`Renderer`](#renderer) bound to one warm device.
- **Throws:** `RenderError` with code `adapter-unavailable` when no compatible
  adapter exists, or `parse` for invalid options.

```typescript
import { createRenderer } from 'nanoraster';

using renderer = await createRenderer({ powerPreference: 'low-power' });
const image = await renderer.renderImage(glb, { format: 'webp' });
```

### `Renderer`

[`createRenderer`](#createrenderer) returns this persistent handle. Its two
render methods mirror the module-level functions exactly: same options, same
results, and byte-identical pixels on the same adapter.

```typescript
export type Renderer = {
  readonly renderImage: (
    glb: Uint8Array<ArrayBuffer>,
    options: RenderImageOptions,
  ) => Promise<RenderedImageFile>;
  readonly renderImages: <const Options extends RenderImagesOptions>(
    glb: Uint8Array<ArrayBuffer>,
    options: StrictRenderImagesOptions<Options>,
  ) => Promise<RenderedImagesResult<Options>>;
  readonly dispose: () => void;
  readonly [Symbol.dispose]: () => void;
};
```

- A renderer is **single-realm**. Create it inside the worker that uses it.
  Bytes cross `postMessage`; handles do not.
- Calls on one renderer run **in sequence**. Send a declared set of images
  through one `renderImages` call, not a loop.
- The next call **recovers device loss**: it rebuilds the device and uploads
  again.
- `dispose()` marks the renderer disposed at once. It is idempotent and
  backs `using` through `Symbol.dispose`. Every later call rejects with
  `RenderError` code `'gpu'`, so create a new renderer instead of retrying.
  GPU teardown follows the queued calls, with no completion signal.

### `describeAdapter`

Describe the adapter that a renderer with these options would bind. Pass the
`powerPreference` that you would pass to `createRenderer`.

```typescript
export declare const describeAdapter: (options?: CreateRendererOptions) => Promise<AdapterInfo | undefined>;
```

the adapter declares itself a fallback. When no adapter exists, the call
resolves `undefined`. Only invalid options reject.

## Options held in a variable

A variable widens `'webp'` to `string` and the view IDs with it, so the
result tuple loses its names. `as const satisfies` keeps the literals and
still checks the keys, at compile time only.

```typescript
import { renderImages, type RenderImagesOptions } from 'nanoraster';

const options = {
  format: 'webp',
  views: [{ id: 'iso' }],
} as const satisfies RenderImagesOptions;

const [iso] = await renderImages(glb, options);
```

`satisfies RenderImageOptions` does the same for the singular call.

## Options

[Frame the model](guides/frame-the-model) and [Place the camera](guides/place-the-camera)
show these fields in use.

### `RenderVector3`

```typescript
export type RenderVector3 = readonly [x: number, y: number, z: number];
```

A Cartesian vector in the request's caller-world frame, which is glTF world
space when the request omits `world`. Direction and up vectors accept any
finite non-zero magnitude, and the renderer normalizes them.

### `RenderWorldAxis`

```typescript
export type RenderWorldAxis = '+x' | '-x' | '+y' | '-y' | '+z' | '-z';
```

One signed principal axis in the caller-world frame.

### `RenderWorld`

```typescript
export type RenderWorld = {
  readonly up?: RenderWorldAxis;
  readonly forward?: RenderWorldAxis;
  readonly unit?: 'meter' | 'millimeter';
};
```

Declares the coordinate frame for camera, section, world-light, axes, and
scale-bar values. It does not change the submitted GLB. The defaults are glTF
`+Y` up, `+Z` forward, and metres. Up and forward must name distinct axes and
form a right-handed frame. Every view in a batch shares the setting.

### `RenderPrimitiveReference`

```typescript
export type RenderPrimitiveReference = {
  readonly nodeIndex: number;
  readonly meshIndex: number;
  readonly primitiveIndex: number;
};
```

One reachable primitive instance in the submitted glTF document. All three
indices are non-negative safe integers. See [Choose visible geometry](guides/choose-visible-geometry).

### `RenderSectionPlane`

```typescript
export type RenderSectionPlane = {
  readonly point: RenderVector3;
  readonly normal: RenderVector3;
};
```

The normal points into the retained world-space half-space. The renderer
normalizes it.

### `RenderSections`

```typescript
export type RenderSections = {
  readonly planes: readonly [RenderSectionPlane, ...RenderSectionPlane[]];
  readonly clipSurfaces?: boolean;
  readonly clipLines?: boolean;
};
```

The request shares one to `renderImageMaxSections` planes. Both clip flags
default to `true`. [Cut section views](guides/render-section-views) covers
caps, outlines, and multiple retained half-spaces. A successful closed-surface
cut contains every cap. A failed cut returns `parse`.

### `RenderCamera`

The tagged camera contract. A fit camera supplies orientation, and nanoraster
solves a geometry-tight optical target, distance, and clipping. A fixed camera
preserves the caller-owned pose and projection. Perspective is rectilinear
and preserves the requested field of view exactly.

```typescript
export type RenderCamera =
  | {
      readonly framing: 'fit';
      readonly direction?: RenderVector3;
      readonly up?: RenderVector3;
      readonly margin?: number;
      readonly projection?:
        | { readonly kind: 'perspective'; readonly verticalFieldOfView?: number }
        | { readonly kind: 'orthographic' };
    }
  | {
      readonly framing: 'fixed';
      readonly position: RenderVector3;
      readonly target: RenderVector3;
      readonly up: RenderVector3;
      readonly projection?:
        | { readonly kind: 'perspective'; readonly verticalFieldOfView?: number; readonly zoom?: number }
        | { readonly kind: 'orthographic'; readonly verticalSpan: number; readonly zoom?: number };
      readonly clipping?: { readonly near: number; readonly far: number };
    };
```

The default fit camera looks from 45 degrees azimuth and 30 degrees
elevation in the declared world, and its `up` is `world.up`. In
glTF world, that direction is `[0.6123724357, 0.5, 0.6123724357]` and that up
is `[0, 1, 0]`. The minimum margin defaults to `0.1`, the perspective field of
view to `45`, and the zoom to `1`. `direction` fixes the orientation from the
subject toward the camera. The fit can translate the optical axis to balance
the projected geometry.

A fixed camera requires a position and target that do not coincide. A view
collinear with `up` names no roll. Screen-up then becomes `world.forward`, or
`world.up` along forward. Omitted clipping derives safe planes from referenced
geometry. The renderer tightens an explicit range outside the referenced
subject, without changing the visible geometry.

### `RenderOrbit`

```typescript
export type RenderOrbit = {
  readonly elevation: number;
  readonly azimuth: number;
};
```

A viewing direction as two angles in degrees around the caller world.
`elevation` is the angle above the world horizontal plane, from `-90` to `90`.
`azimuth` is the angle in that plane, zero on `world.forward` and positive
toward the viewer's right.

### `directionFromOrbit`

```typescript
export declare const directionFromOrbit: (orbit: RenderOrbit, world?: RenderWorld) => RenderVector3;
```

- **Parameters:** the orbit angles, and the world they are measured in. Pass
  the request's `world`, or omit it for the glTF default.
- **Returns:** the unit `direction` that a fitted camera takes.
- **Throws:** `TypeError` for a non-finite azimuth, an elevation outside
  `-90` to `90`, or an invalid world.

```typescript
import { directionFromOrbit } from 'nanoraster';

const world = { up: '+z', forward: '-y' } as const;
const direction = directionFromOrbit({ azimuth: 45, elevation: 30 }, world);
```

### `orbitFromDirection`

```typescript
export declare const orbitFromDirection: (direction: RenderVector3, world?: RenderWorld) => RenderOrbit;
```

- **Parameters:** any finite non-zero direction, and the world it is
  expressed in. The function ignores the magnitude.
- **Returns:** the orbit angles that reproduce the direction. The result
  exactly inverts [`directionFromOrbit`](#directionfromorbit) in the same
  world. The azimuth is above `-180` and up to `180`. At the poles, elevation
  `-90` or `90`, the azimuth is undefined and reported as `0`.
- **Throws:** `TypeError` for a zero or non-finite direction, or an invalid
  world.

### `StrictRenderImagesOptions`

The exact parameter type of [`renderImages`](#renderimages) and
`Renderer.renderImages`. It narrows `RenderImagesOptions` so that extra keys,
empty view tuples, and per-view settings at call level are compile errors.
Callers pass plain `RenderImagesOptions` literals. Name it only when you
forward the plan call through a generic wrapper:

```typescript
import { renderImages, type RenderImagesOptions, type StrictRenderImagesOptions } from 'nanoraster';

const renderCatalogue = async <const Options extends RenderImagesOptions>(
  glb: Uint8Array<ArrayBuffer>,
  options: StrictRenderImagesOptions<Options>,
) => renderImages(glb, options);
```

### `RenderLighting`

```typescript
export type RenderLighting = 'studio' | RenderLightingRig;
```

The studio preset by name, or a rig. Three requests render the same bytes:
omit `lighting`, pass `'studio'`, or state the studio values in full. One rig
applies to every view of a batch. [Light the subject](guides/light-the-subject)
shows each field in use.

### `RenderLightingRig`

A rig replaces the studio lights outright. It inherits every other studio
value that it leaves out. Directions are view-space by default: `+x` right,
`+y` up, `+z` toward the viewer. `space: 'world'` uses the declared caller
world.

## Results

### `RenderedImageFile`

[`renderImage`](#renderimage) returns this type, and every batch entry carries
it as `file`. `width` and `height` are the resolved request dimensions. With `format: 'raw'`, `bytes` is the frame itself: straight-alpha sRGB
RGBA8, `width * height * 4` bytes, top row first. Its `mimeType` is then
`application/octet-stream`. [Work with raw pixels](guides/work-with-raw-pixels)
has the layout in full.

```typescript
import { renderImage } from 'nanoraster';

import { writeFile } from 'node:fs/promises';

const image = await renderImage(glb, { format: 'webp' });
await writeFile(image.name, image.bytes);
```

One identified entry in a batch result. The `id` is the literal from the

### `RenderedImages`

The ordered tuple inside every plan-call result.

```typescript
export type RenderedImages<
  Views extends readonly RenderImageView[],
  SharedFormat extends ImageFormat = ImageFormat,
> = {
  readonly [Index in keyof Views]: Views[Index] extends RenderImageView<infer Id>
    ? RenderedImage<Id, ViewOutputFormat<Views[Index], SharedFormat>>
    : never;
};
```

This mapped tuple preserves each input view's literal ID, position and length.
It narrows each entry's MIME type through the view's `format` override,
falling back to the shared format. Entry files are named
`render-<id>.<format>`.

### `RenderedImagesResult`

The type that [`renderImages`](#renderimages) resolves to. It is the
[`RenderedImages`](#renderedimages) tuple, plus a
[`RenderTimings`](#rendertimings) on `timings` when the options literal set
`timings: true`. A read of `timings` without that request is a compile error.

```typescript
import { renderImages, type RenderedImagesResult, type RenderImagesOptions } from 'nanoraster';

const options = {
  format: 'webp',
  timings: true,
  views: [{ id: 'iso' }],
} as const satisfies RenderImagesOptions;

const result: RenderedImagesResult<typeof options> = await renderImages(glb, options);
console.log(result[0].file.name, result.timings.parse); // 'render-iso.webp' 0.42
```

### `RenderTimings`

A plan call's result carries this type when the options set `timings: true`.
The fields map onto the [pipeline stages](how-it-works): parse, shared
cap-build, source upload, then per-view rasterise, annotate and encode.
Resource counters show which work the call acquired. `presentationBuilds` is
`1` for one plan.

## Errors

Rendering rejects with `RenderError`. Parse and encode failures are
deterministic for the same request. GPU faults can succeed after the host
recovers, so [Handle render failures](guides/handle-render-failures) retries
them.

### `RenderFailureCode`

```typescript
export type RenderFailureCode =
  | 'adapter-unavailable'
  | 'device-lost'
  | 'driver-unsupported'
  | 'gpu'
  | 'parse'
  | 'encode'
  | 'unknown';
```

| Value                 | Meaning                                                      | Retry guidance                                              |
| --------------------- | ------------------------------------------------------------ | ----------------------------------------------------------- |
| `adapter-unavailable` | No compatible GPU adapter was available.                     | Keep the last image and retry after host recovery.          |
| `device-lost`         | The GPU device was lost during rendering.                    | Keep the last image and retry with a new device.            |
| `driver-unsupported`  | The host's GPU driver faults mid-render on 32-bit ARM Linux. | Render on another driver, or set the documented opt-out.    |
| `gpu`                 | Another adapter, driver, or render-pass failure occurred.    | Treat as transient unless host diagnostics prove otherwise. |
| `parse`               | GLB bytes or request options violated the input contract.    | Fix the input before retrying.                              |
| `encode`              | The selected encoder could not produce the requested image.  | Fix the format or background before retrying.               |
| `unknown`             | The thrown value had no recognised failure tag.              | Inspect `message` and preserve the original context.        |

### `RenderError`

`RenderError` extends `Error` and adds this public surface:

```typescript
export declare class RenderError extends Error {
  readonly code: RenderFailureCode;
  constructor(code: RenderFailureCode, message: string);
  static from(error: unknown): RenderError;
  get isGpuFault(): boolean;
}
```

`RenderError.from(error)` returns an existing `RenderError` unchanged and
classifies any other thrown value. It never throws. `isGpuFault` is
`true` for `adapter-unavailable`, `device-lost` and `gpu`.

```typescript
import { RenderError, renderImage } from 'nanoraster';

try {
  await renderImage(glb, { format: 'webp' });
} catch (error) {
  const failure = RenderError.from(error);
  if (!failure.isGpuFault) throw failure;
}
```

### `renderImageDimensionRange`

Inclusive bounds for both image dimensions.

### `renderImageMarginRange`

Inclusive minimum fitted-margin bounds.

### `renderImageVerticalFieldOfViewRange`

Inclusive vertical perspective field-of-view bounds.

### `renderImageZoomRange`

Inclusive perspective and orthographic magnification bounds.

### `renderImageLineWidthRange`

Inclusive authored-edge line-width bounds.

### `renderImageAnnotatedMinDimension`

Minimum width and height when any annotation is enabled.

### `renderImageQualityRange`

Inclusive encoder-quality bounds. JPEG treats the value as a compression
level, with default `0.92`. WebP defaults to `1`, lossless, and treats any
lower value as lossy. PNG and raw ignore the value.

### `renderImageBackgroundPattern`

The hex clear-colour syntax. It does not cover normalised straight-alpha RGBA
backgrounds.

### `renderImageLabelMaxLength`

Maximum label length.

### `renderImageLabelPattern`

Supported label characters: printable ASCII plus the micro sign, em dash, and
minus sign.

### `renderImageViewIdPattern`

The view identifier syntax. IDs become filenames, so the pattern restricts
the first character.

### `renderImageMaxLights`

The directional-light cap for one rig.

### `renderImageMaxSections`

The simultaneous retained-half-space plane cap for one request.

### `renderImageLightColorRange`

Inclusive per-channel bounds for a light's radiance.

### `renderImageAmbientRange`

Inclusive bounds for the rig's flat ambient multiplier.

### `renderImageExposureRange`

Inclusive bounds for the pre-tone-map exposure multiplier.
