title: Render a view sheet
description: Build a four-view contact sheet from one GLB, learning batch rendering, fitted cameras, and labels along the way.

Build a labelled four-view contact sheet (front, right, top and iso) from one
GLB in a single render call.

## Step 1: Render a single fitted view

Start with one view so the camera controls are visible on their own.
[Frame the model](guides/frame-the-model) explains `direction` and `up`.

<RenderDemo>

```typescript
import { renderImage } from 'nanoraster';

import { readFile, writeFile } from 'node:fs/promises';

const glb = Uint8Array.from(await readFile('model.glb'));

const front = await renderImage(glb, {
  format: 'webp',
  width: 512,
  height: 512,
  camera: { framing: 'fit', direction: [1, 0, 0] },
});

await writeFile('front.webp', front.bytes);
```

</RenderDemo>

**Verify**: `front.webp` shows the gear face-on, teeth all round the rim.

## Step 2: Switch to the batch call

Rendering each view with its own call parses and uploads the GLB every time.
`renderImages` does that once and renders every view in the list — start
with two, then add the rest in step 3. A sheet wants a tighter fit than a
single hero image, so each preset uses `margin: 0.05`.

<RenderDemo>

```typescript
import { renderImages } from 'nanoraster';

import { readFile, writeFile } from 'node:fs/promises';

const glb = Uint8Array.from(await readFile('model.glb'));

const sheet = await renderImages(glb, {
  format: 'webp',
  width: 512,
  height: 512,
  views: [
    { id: 'front', camera: { framing: 'fit', direction: [1, 0, 0], margin: 0.05 } },
    { id: 'right', camera: { framing: 'fit', direction: [0, 0, -1], margin: 0.05 } },
  ],
});

for (const { id, file } of sheet) {
  await writeFile(file.name, file.bytes);
  console.log(id, file.name);
}
```

</RenderDemo>

**Verify**: two files appear, and the console prints the IDs in the order you
declared them:

```console
front render-front.webp
right render-right.webp
```

The result filename carries the view `id`, not a counter.

## Step 3: Add the top and iso views

The top view looks down the up axis; the iso view is the default three-quarter
angle. `axes` draws a camera-aware marker in each image, which is what
orients the top view once it is on its own.

<RenderDemo>

```typescript
const sheet = await renderImages(glb, {
  format: 'webp',
  width: 512,
  height: 512,
  axes: true,
  views: [
    { id: 'front', camera: { framing: 'fit', direction: [1, 0, 0], margin: 0.05 } },
    { id: 'right', camera: { framing: 'fit', direction: [0, 0, -1], margin: 0.05 } },
    { id: 'top', camera: { framing: 'fit', direction: [0, 1, 0], up: [0, 0, 1], margin: 0.05 } },
    { id: 'iso', camera: { framing: 'fit', direction: [0.6123724357, 0.5, 0.6123724357], margin: 0.05 } },
  ],
});
```

</RenderDemo>

**Verify**: four files. `render-top.webp` looks down at the model, and `render-iso.webp` uses
[the quick start's direction](/docs).

## Step 4: Label each view

Labels are drawn into the image, screen-upright, so a sheet stays readable
once the images are separated from their filenames. A view carries one when
its entry sets `label`; there is no flag to turn on, and clearing a label
below removes it. `scaleBar` adds the bottom-left bar, so the finished sheet
carries its own units too.

<RenderDemo>

```typescript
const sheet = await renderImages(glb, {
  format: 'webp',
  width: 512,
  height: 512,
  axes: true,
  scaleBar: true,
  views: [
    { id: 'front', camera: { framing: 'fit', direction: [1, 0, 0], margin: 0.05 }, label: 'Front' },
    { id: 'right', camera: { framing: 'fit', direction: [0, 0, -1], margin: 0.05 }, label: 'Right' },
    {
      id: 'top',
      camera: { framing: 'fit', direction: [0, 1, 0], up: [0, 0, 1], margin: 0.05 },
      label: 'Top',
    },
    {
      id: 'iso',
      camera: { framing: 'fit', direction: [0.6123724357, 0.5, 0.6123724357], margin: 0.05 },
      label: 'Iso',
    },
  ],
});
```

</RenderDemo>

**Verify**: each image carries its name in the top-left corner.

## Step 5: Keep it reproducible

Run the script twice and compare the files: the sheet regenerates
byte-for-byte on the same host. [How it works](how-it-works#determinism) sets out what is
and is not guaranteed across hosts.
