nanoraster turns a GLB file into image bytes you own. It runs headless in Node.js
on a native binary, and in the browser on WebGPU, from one Rust render core.

The same request produces the same pixels on the same host, which is what makes
the output usable as evidence in a CAD pipeline or an agent loop rather than
just as a picture.

## What it does

- **One call per image, or one call per set.** [`renderGlbToImage`](api/operations)
  renders a single camera view; [`renderGlbToImages`](api/operations) parses and
  uploads the GLB once, then renders an ordered tuple of identified views.
- **Four output formats.** PNG, WebP, and JPEG, with `jpg` as an alias. See
  [Choose a format and quality](guides/choose-format-and-quality).
- **Typed failures.** Every rejection is a `RenderError` carrying a stable
  machine-readable code. See [Handle render failures](guides/handle-render-failures).
- **Lighting fixed by default.** Every render uses one studio rig unless you
  supply your own, which is what keeps repeated renders comparable. See
  [Determinism](concepts/determinism) and
  [Light the subject](guides/light-the-subject).

## What it does not do

- Texture-backed materials. The supported profile is factor-only glTF
  metallic-roughness — see [Material model](concepts/material-model).
- Animation, scene graphs beyond static geometry, or physically-measured
  lighting.
