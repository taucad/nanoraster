Build a labelled four-view contact sheet — front, right, top, and iso — from a
single GLB, in one render call.

## What you'll learn

- How to render several camera views without reparsing the GLB.
- How `phi` and `theta` place a camera, and how the up axis changes them.
- How view IDs flow through to result filenames and tuple order.
- When to turn on labels and axes, and what they cost.
- How to keep the whole sheet reproducible.

## Prerequisites

- Completed the [Quick start](quick-start).
- A GLB file saved as `model.glb`.
- Node.js 24 or newer.

## Step 1: Render a single view off the default angle

Start from one view so the camera controls are visible in isolation. `phi` is
the polar angle away from the up axis; `theta` is the azimuth around it.

```typescript
import { renderGlbToImage } from 'nanoraster';

import { readFile, writeFile } from 'node:fs/promises';

const glb = Uint8Array.from(await readFile('model.glb'));

const front = await renderGlbToImage(glb, {
  format: 'png',
  width: 512,
  height: 512,
  phi: 90,
  theta: 0,
});

await writeFile('front.png', front.bytes);
```

**Verify**: `front.png` exists and shows the model edge-on rather than from
above. `phi: 90` puts the camera on the equator — level with the model — and
`theta: 0` puts it on the primary axis.

## Step 2: Switch to the batch call

Rendering four views with four separate calls parses and uploads the GLB four
times. `renderGlbToImages` does that work once and then renders each view.

```typescript
import { renderGlbToImages } from 'nanoraster';

import { readFile, writeFile } from 'node:fs/promises';

const glb = Uint8Array.from(await readFile('model.glb'));

const sheet = await renderGlbToImages(glb, {
  format: 'png',
  width: 512,
  height: 512,
  views: [
    { id: 'front', phi: 90, theta: 0 },
    { id: 'right', phi: 90, theta: 90 },
  ],
});

for (const { id, file } of sheet) {
  await writeFile(file.name, file.bytes);
  console.log(id, file.name);
}
```

**Verify**: two files appear, and the console prints the IDs in the order you
declared them:

```console
front front.png
right right.png
```

The result filename comes from the view `id`, not from a counter. IDs must be
unique and match `[A-Za-z0-9][A-Za-z0-9_-]{0,63}`.

## Step 3: Add the top and iso views

The top view looks straight down the up axis, so `phi` goes to 0 and `theta`
stops mattering. The iso view is the default three-quarter angle.

```typescript
const sheet = await renderGlbToImages(glb, {
  format: 'png',
  width: 512,
  height: 512,
  views: [
    { id: 'front', phi: 90, theta: 0 },
    { id: 'right', phi: 90, theta: 90 },
    { id: 'top', phi: 0, theta: 0 },
    { id: 'iso', phi: 60, theta: -45 },
  ],
});
```

**Verify**: four files. `top.png` looks down at the model; `iso.png` matches
what the [Quick start](quick-start) produced, because those are the default
angles.

## Step 4: Label each view

Labels are rendered into the image, screen-upright, so a sheet stays readable
once the images are separated from their filenames. Turning them on makes
`label` required on every view.

```typescript
const sheet = await renderGlbToImages(glb, {
  format: 'png',
  width: 512,
  height: 512,
  includeLabel: true,
  views: [
    { id: 'front', phi: 90, theta: 0, label: 'Front' },
    { id: 'right', phi: 90, theta: 90, label: 'Right' },
    { id: 'top', phi: 0, theta: 0, label: 'Top' },
    { id: 'iso', phi: 60, theta: -45, label: 'Iso' },
  ],
});
```

**Verify**: each image carries its name in the top-left corner. If you omit one
`label`, TypeScript rejects the call before it runs — the type of `views`
changes when `includeLabel` is `true`.

## Step 5: Keep it reproducible

Two settings decide whether this sheet can be regenerated byte-for-byte later:
an explicit background, and dimensions at or above the annotated minimum.

```typescript
const sheet = await renderGlbToImages(glb, {
  format: 'png',
  width: 512,
  height: 512,
  background: '#0c1015',
  includeLabel: true,
  includeAxes: true,
  views: [
    { id: 'front', phi: 90, theta: 0, label: 'Front' },
    { id: 'right', phi: 90, theta: 90, label: 'Right' },
    { id: 'top', phi: 0, theta: 0, label: 'Top' },
    { id: 'iso', phi: 60, theta: -45, label: 'Iso' },
  ],
});
```

**Verify**: every image now has an opaque dark background and an axis indicator
in the bottom-right. Run the script twice and compare the files — they are
identical, because nothing in the request depends on wall-clock time, ambient
state, or a random seed.

## Recap

You built a four-view sheet from one GLB in one call. Along the way:

- `renderGlbToImages` parses and uploads once, then renders each view.
- `phi` is polar from the up axis, `theta` is azimuth around it. `phi: 0` looks
  straight down that axis.
- View IDs become result filenames and preserve tuple order.
- `includeLabel: true` makes `label` mandatory at the type level.
- A fixed request produces fixed bytes.
