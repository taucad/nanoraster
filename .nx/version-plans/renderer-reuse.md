---
nanoraster: minor
---

Add a handles-first renderer surface. `createRenderer` returns a persistent `Renderer` that keeps the GPU device, shader, and pipelines alive across calls (with `dispose()` and `using` support, transparent device-loss recovery, and byte-identical output to the one-shot functions, which remain unchanged as sugar). Plan entries in `renderImages` gain per-view `width`, `height`, `format`, and `quality` overrides that flow into per-entry filenames and literal MIME types, and `profile: true` attaches typed stage timings to the result. New `renderPixels` returns raw straight-alpha RGBA without an encode, and `describeAdapter` names the selected backend and device so software adapters are detectable. Internally the core executes each plan in one pipelined pass — the next view's GPU work is submitted while the previous view encodes, with parallel encodes on native — and the Node addon now renders on the libuv thread pool, so every native render entry point returns a Promise instead of blocking the event loop (breaking for direct addon consumers under the prerelease policy; the `nanoraster` package API was already Promise-based).

Rename the render family (breaking, under the prerelease policy, with no aliases left behind). `renderGlbToImage`, `renderGlbToImages`, and `renderGlbToPixels` — free functions and `Renderer` methods alike — become `renderImage`, `renderImages`, and `renderPixels`; the input type never belonged in the verb, and every neighbouring export already used the unqualified stem. The native addon and the wasm class rename with them (`renderImage`/`renderImages`/`renderPixels` and `render_image`/`render_images`/`render_pixels`), which is breaking for direct addon consumers. Synthesized filenames become `render.<format>` and `render-<id>.<format>` instead of `thumbnail.*`, because the library renders anything, not thumbnails. The `createRenderImageOptions` and `createRenderImagesOptions` identity helpers are deleted: `{ … } as const satisfies RenderImageOptions` keeps the literal view IDs and formats, rejects misspelled and misplaced keys at the offending property, and costs no runtime call. `RenderedImagesResult` and `StrictRenderImagesOptions` are now exported — the public `Renderer` type referenced both, so consumers could not name its parameter or return type. Rendered bytes are unchanged.

Sharpen the annotation options (breaking, under the prerelease policy). `includeLabel` is deleted: a `label`'s presence is the switch, so setting one draws it and omitting one does not — which also ends the rule that a batch call must label every view, letting a sheet label some and not others. `includeAxes` and `includeScale` become `axes` and `scaleBar`, on the wire as well as in TypeScript; the `include` prefix did no disambiguating work, and `scaleBar` beats a bare `scale` that would read as image scaling next to `width` and `height`. The coupling types and the four runtime checks that enforced `includeLabel` against `label` are gone with it. Annotated renders keep byte-identical output under the new spelling.

The one-shot functions — `renderImage`, `renderImages`, and `renderPixels` — now route through one lazily created renderer per process instead of building and destroying a GPU device per call. The first call pays the bring-up and later calls reuse it (measured 27 ms then 3.4 ms at 768×576 on an Apple M2 Pro), calls run in sequence in call order, so `Promise.all` over one-shot renders no longer races several GPU devices, and output stays byte-identical. That renderer uses the default `'high-performance'` power preference and lives until the process or worker exits; hold a `createRenderer` handle when the lifetime or the preference matters. Render targets above 2048² are dropped after each one-shot call, so a single large render does not pin GPU memory for the life of the process.
