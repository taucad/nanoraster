---
nanoraster: minor
---

Add a handles-first renderer surface. `createRenderer` returns a persistent `Renderer` that keeps the GPU device, shader, and pipelines alive across calls (with `dispose()` and `using` support, transparent device-loss recovery, and byte-identical output to the one-shot functions, which remain unchanged as sugar). Plan entries in `renderImages` gain per-view `width`, `height`, `format`, and `quality` overrides that flow into per-entry filenames and literal MIME types, and `timings: true` attaches typed stage timings to the result. New `renderPixels` returns raw straight-alpha RGBA without an encode, and `describeAdapter` names the selected backend and device so software adapters are detectable. Internally the core executes each plan in one pipelined pass — the next view's GPU work is submitted while the previous view encodes, with parallel encodes on native — and the Node addon now renders on the libuv thread pool, so every native render entry point returns a Promise instead of blocking the event loop (breaking for direct addon consumers under the prerelease policy; the `nanoraster` package API was already Promise-based).

Rename the render family (breaking, under the prerelease policy, with no aliases left behind). `renderGlbToImage`, `renderGlbToImages`, and `renderGlbToPixels` — free functions and `Renderer` methods alike — become `renderImage`, `renderImages`, and `renderPixels`; the input type never belonged in the verb, and every neighbouring export already used the unqualified stem. The native addon and the wasm class rename with them (`renderImage`/`renderImages`/`renderPixels` and `render_image`/`render_images`/`render_pixels`), which is breaking for direct addon consumers. Synthesized filenames become `render.<format>` and `render-<id>.<format>` instead of `thumbnail.*`, because the library renders anything, not thumbnails. The `createRenderImageOptions` and `createRenderImagesOptions` identity helpers are deleted: `{ … } as const satisfies RenderImageOptions` keeps the literal view IDs and formats, rejects misspelled and misplaced keys at the offending property, and costs no runtime call. `RenderedImagesResult` and `StrictRenderImagesOptions` are now exported — the public `Renderer` type referenced both, so consumers could not name its parameter or return type. Rendered bytes are unchanged.

Sharpen the annotation options (breaking, under the prerelease policy). `includeLabel` is deleted: a `label`'s presence is the switch, so setting one draws it and omitting one does not — which also ends the rule that a batch call must label every view, letting a sheet label some and not others. `includeAxes` and `includeScale` become `axes` and `scaleBar`, on the wire as well as in TypeScript; the `include` prefix did no disambiguating work, and `scaleBar` beats a bare `scale` that would read as image scaling next to `width` and `height`. The coupling types and the four runtime checks that enforced `includeLabel` against `label` are gone with it. Annotated renders keep byte-identical output under the new spelling.

The one-shot functions — `renderImage`, `renderImages`, and `renderPixels` — now route through one lazily created renderer per process instead of building and destroying a GPU device per call. The first call pays the bring-up and later calls reuse it (measured 27 ms then 3.4 ms at 768×576 on an Apple M2 Pro), calls run in sequence in call order, so `Promise.all` over one-shot renders no longer races several GPU devices, and output stays byte-identical. That renderer uses the default `'high-performance'` power preference and lives until the process or worker exits; hold a `createRenderer` handle when the lifetime or the preference matters. Render targets above 2048² are dropped after each one-shot call, so a single large render does not pin GPU memory for the life of the process.

Rename the stage-timings surface (breaking, under the prerelease policy). The `profile` option and result property are now `timings`, `RenderProfile` and `RenderViewProfile` are `RenderTimings` and `RenderViewTimings`, and every duration field drops its `Ms` suffix: `parseMs`/`setupMs` become `parse`/`setup`, and a view's `renderMs`/`overlayMs`/`encodeMs` become `render`/`overlay`/`encode`. `timings` names what the data is rather than what you did to get it, and the unit lives in the documentation — every duration is milliseconds, as it always was, so no value changes. The wire field renames with it (`timings` in the request, `timings`/`parse`/`setup`/`render`/`overlay`/`encode` in the reply), which is breaking for direct consumers of the native addon and the wasm class. Rendered bytes are unchanged.

Report the adapter as data instead of prose (breaking, under the prerelease policy). `describeAdapter` returns an `AdapterInfo` — `{ backend, name, deviceType }` — rather than a string like `"Metal / Apple M2 Pro (IntegratedGpu)"`, so `adapter.deviceType === 'cpu'` replaces a substring match for software rasterization, and `backend` and `name` are readable without parsing. It also takes the `CreateRendererOptions` that `createRenderer` takes: `describeAdapter({ powerPreference: 'low-power' })` describes the adapter that renderer would bind, where the old call always described the high-performance one. Browsers now answer from `navigator.gpu` in TypeScript, so the preflight costs no wasm download and reports what the browser actually discloses (`"google swiftshader"` in headless Chrome, `"apple"` in Safari, `""` in Firefox) instead of the blank name wgpu's web backend passed through; `deviceType` is `'unknown'` there unless the adapter declares itself a fallback, because WebGPU withholds the class. The wasm artifact drops its `describe_adapter` export and 2,545 bytes with it, and the native addon's `describeAdapter` takes the options JSON and returns the same JSON the façade parses.

Drop the benchmark surface from every published artifact (breaking, under the prerelease policy). `benchCodecs`, `benchMultiView` and `codecConformance` on the native addon, and `bench_codecs`, `bench_multi_view` and `codec_conformance` on the wasm module, now sit behind a default-off `bench` cargo feature: they are development instrumentation, and benching belongs outside what consumers install. The wasm artifact loses 50,693 bytes (5.5 percent of it, 347,393 gzipped against 366,233) and the macOS addon 33,184; the documentation demo serves the smaller wasm too. Rendering is untouched, so every rendered byte is unchanged — proven by rendering the same requests through a feature-enabled sibling build of the same source, which is also what the benchmark and the browser codec-fingerprint gate now measure.

Require a `format` on every image request at the wire (breaking for direct consumers of the native addon and the wasm module, under the prerelease policy). `format` has always been mandatory in TypeScript — deliberately, so a better default can be adopted later without an API break — which left the render core's `"png"` fallback unreachable from the package. That fallback is deleted: a request naming no format now fails with `parse: format is required` rather than quietly producing a PNG. The raw-pixels request is unaffected, because it encodes nothing and carries no format at all. Rendered bytes are unchanged.

Gate the codec fingerprints instead of asserting them in comments. The vendored image-webp update that brought lossy encoding also dropped this fork's deterministic Huffman tie-break, so lossless WebP bytes had come apart between the native addon and the wasm module — same size, different bytes, on every fixture where Huffman length limiting runs. The tie-break is restored (lossless WebP bytes change once more, and the two artifacts agree again), the GPU-free conformance fixtures gain a lossy-WebP fingerprint per case so the newest and only forked encoder is covered too, and both the render core's own suite and the three-browser suite now assert against one committed fingerprint table — so a codec that drifts on either artifact fails CI. PNG, JPEG, and every rendered pixel are unchanged.

Collapse `renderPixels` into a fourth output format (breaking, under the prerelease policy, with no aliases left behind). `renderImage(glb, { format: 'raw' })` is the singular raw path and `renderImages` with raw views is the plural one, so `renderPixels`, `Renderer.renderPixels`, `RenderPixelsOptions` and `RenderedPixels` are deleted — along with the native addon's `renderPixels` and the wasm module's `render_pixels`, which is breaking for direct addon consumers. A raw result is an ordinary `RenderedImageFile`: `bytes` is the frame rather than an encoded file — straight-alpha, sRGB-encoded RGBA8, exactly `width * height * 4` bytes, row-major with the top row first, four bytes per pixel and no padding — named `render.raw` or `render-<id>.raw` with `imageMimeTypes.raw` (`application/octet-stream`). `quality` is ignored for raw exactly as PNG ignores it, so no new validation rule appears. Two capabilities come free: a turntable is one plan call of raw views, and a plan may mix them with encoded ones (a WebP thumbnail beside an unencoded frame). Every rendered and encoded byte is unchanged; the wasm artifact loses 9,589 bytes with the deleted entry points.

Report the resolved output shape on every result. `RenderedImageFile` gains `readonly width` and `readonly height` for every format, resolved façade-side from the request (per-view overrides falling back to the shared value, then to 768×432), so a result can be read, diffed, uploaded, or wrapped in an `ImageData` without a second lookup — which raw output needs and encoded output was quietly missing. There is no wire change and no rendered byte changes.
